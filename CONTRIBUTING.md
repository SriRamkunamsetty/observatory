# Contributing

1. `python -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt`
2. `make test` and `make lint` must pass before you open a PR.
3. Add or update tests for every behaviour change; keep PRs small and focused.
4. Security-relevant changes need a test that fails without the fix.
5. Use conventional commit messages (`feat:`, `fix:`, `docs:`, `test:`).

Good first issues are labelled `good first issue`. Be kind and constructive in reviews.
